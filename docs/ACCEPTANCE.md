# CPBL Scouting Lab — 驗收規格

本文件在重做開始前訂定，是判斷專案「完成」的唯一標準。每一條驗收項目都對應到可自動執行的測試，
最終 PR 必須逐條附上證據（測試名稱或 CI job），全部通過才算完成。

## 0. 範圍與架構決策

| 項目 | 決策 |
| --- | --- |
| 資料來源 | 沿用 CPBL 官方公開頁面的已驗證快照（`data/processed/`），不新增非官方來源 |
| 分析核心 | Python（`src/`），新增 `src/analytics/` 模組，全部可離線、可重現 |
| 前端 | 全新 React + TypeScript + Vite 靜態網站（`web/`），部署於 GitHub Pages |
| 舊版 Streamlit | 移除（`app.py`、Streamlit 專屬測試與 UI QA），由新網站與新測試取代 |
| 模擬運算 | 在瀏覽器 Web Worker 執行，固定亂數種子可重現 |
| 外部服務 | 執行期不呼叫任何第三方網址、不需要 API 金鑰 |

## 1. 功能驗收（創新功能）

### F1 聯盟脈動（首頁）
- 顯示 6 隊戰績、勝率、得失分差，以及 **畢氏期望勝率** 與「運氣差」（實際勝場 − 期望勝場）。
- 顯示資料快照時間、資料年齡與品質狀態，不冒充即時資料。
- 驗收：畢氏勝率公式單元測試；首頁 E2E 顯示 6 隊且數值與匯出資料一致。

### F2 真實實力估計（Empirical Bayes）
- 打者：上壘率、三振率、保送率、全壘打率；投手：三振率、保送率、FIP。
- 以聯盟分布用動差法估計 Beta 先驗，輸出後驗平均與 80% 可信區間，標示「小樣本陷阱」（原始值與後驗差距大）。
- 介面可切換「原始值／收縮後」排序，並視覺化區間。
- 驗收（單元測試）：
  - 後驗平均介於原始值與聯盟平均之間；
  - 樣本數越大區間越窄；
  - 樣本數為 0 時後驗等於先驗平均；
  - 先驗參數為有限正值。

### F3 打線實驗室（Monte Carlo 模擬）
- 使用者選 9 名打者與 1 名對手投手，以 log5 結合打者與投手事件機率，在 Web Worker 中用壘包－出局數馬可夫模擬整場比賽。
- 輸出：每場期望得分、得分分布直方圖、「得 5 分以上機率」；提供 **最佳化棒次**（局部搜尋）並顯示與原棒次的差異及信賴區間。
- 可取消、顯示進度；同一種子結果完全相同。
- 驗收（單元測試）：
  - 壘包推進規則（保送擠壘、一壘安打、長打、全壘打清壘）逐一驗證；
  - 全員全壘打打線每個打席得 1 分；
  - 全員三振打線得 0 分；
  - 同種子輸出相同；
  - 聯盟平均打線的模擬每場得分落在聯盟實際每場得分 ±20% 內。

### F4 季末戰績模擬
- 依各隊畢氏強度與 log5 對戰機率模擬剩餘賽程 10,000 次，輸出最終勝場分布與「奪得第一機率」。
- 驗收：
  - 各隊奪冠機率總和為 1（±1e-9）；
  - 已打完全部賽程的隊伍勝場固定；
  - 同種子結果相同。

### F5 球員檔案
- 聯盟百分位條（同類型球員）。
- 跨 17 份快照的指標軌跡圖與趨勢判讀。
- **相似球員**：標準化特徵的餘弦相似度前 5 名，並顯示各特徵的貢獻。
- **自動球探摘要**：模板式自然語言生成，每一句都附上對應的數據證據，不使用任何外部模型。
- 驗收：
  - 相似度排除自己，且結果依相似度排序；
  - 摘要每句都能對應到至少一個指標；
  - 不得出現未填入的模板變數。

### F6 比較與分享
- 最多 3 名球員並列比較；CSV／JSON 匯出（含 CSV 公式注入防護）。
- 網址保存目前畫面狀態，可直接分享。
- 驗收：E2E 驗證下載內容欄位正確；重新載入分享網址後狀態還原。

### F7 資料可信度
- 快照時間軸、品質檢查結果、公開清單 SHA-256、方法說明與限制。
- 驗收：E2E 顯示快照數與 manifest 中的 release_id 一致。

## 3. 完成定義

1. F1–F7 與 Q1–Q10 全部通過，並在 PR 中逐條附上證據。
