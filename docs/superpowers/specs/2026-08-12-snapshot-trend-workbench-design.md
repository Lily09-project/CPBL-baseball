# CPBL 版本趨勢工作區設計

## 目標

把既有的官方資料快照、SHA-256 血緣與球員成績轉成可操作的版本比較功能，讓作品同時展示資料擷取、版本化、品質驗證、歷史分析與前端解釋能力。

## 使用者工作流程

1. 從側邊欄進入「版本趨勢」。
2. 先閱讀資料版本數、涵蓋期間、最新版本與 schema 漂移狀態。
3. 選擇球員與指標，檢視跨版本折線與實際值表格。
4. 選擇基準與比較版本，查看新增、移除、變動與不變球員。
5. 匯出畫面上相同的版本差異表，供後續分析或面試展示。

## 資料架構

`src/history.py` 負責讀取 `data/snapshots/**/manifest.json`，依 `captured_at` 穩定排序，輸出兩份可公開資料：

- `data/processed/snapshot_history.csv`：每個版本一列，包含版本 ID、時間、品質狀態、前一版本、列數與變更摘要。
- `data/processed/player_metric_history.csv`：每位有官方成績的球員在每個版本一列，保留身份欄位與可比較的打者／投手指標。

前端只讀取這兩份衍生資料，不依賴部署環境中被忽略的 `data/snapshots/`。`run_all.py` 在品質檢查、快照與 movement 產生後重建歷史輸出，並把摘要寫入資料品質報告。

## 比較規則

- 同一 `player_id` 在兩個版本間以外連接比較。
- 只存在比較版本者為 `new`，只存在基準版本者為 `removed`。
- 兩邊都有且數值不同者為 `changed`，相同者為 `unchanged`。
- `ERA`、`WHIP`、`BB%`、`HR%` 等低者較佳指標，`favorable_delta` 反轉符號；其他指標維持原差值。
- 缺值不製造假的 0 或差值。
- 比較版本必須晚於基準版本；無效版本或指標回傳空表並由 UI 顯示說明。

## 介面方向

延續目前深色編輯台風格，以時間軸、精簡狀態卡、原生選擇器、折線圖和資料表構成。卡片維持相同高度與 24px 桌面間距、16px 行動裝置間距。所有圖表提供文字摘要，英文棒球縮寫維持大寫。

## 安全與隱私

- 不輸出原始 HTML、環境變數、憑證、本機絕對路徑或完整快照檔案。
- 球員主鍵沿用 CPBL 官方 `player_id`，保留前導零。
- CSV 匯出沿用既有公式注入防護。
- 公開歷史檔只包含已公開於目前處理後 CSV 的欄位。

## 驗證

- 單元測試：快照排序、輸出 schema、缺檔、重複 ID、指標正負向、新增／移除／不變狀態。
- 管線測試：`run_all.py` 產生兩份歷史檔並寫入品質報告。
- Streamlit 測試：頁面可渲染、控制項可互動、圖表摘要、中文與棒球術語正確。
- 完整檢查：全套 pytest、smoke test、Bandit、detect-secrets、pip-audit、Git 差異與桌面／平板／手機視覺檢查。
